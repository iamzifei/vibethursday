| | |
|---|---|
| **要收什么** | 背景 / 人群画像（自由职业·企业主·独立开发·学生上班）、想聊的方向、时间偏好 |

## 六、成员墙：报名**不会**自动上墙（2026-08-13 实测，回应群里的反馈）

> 群里的反馈：「报名的时候就直接把大家填入的信息放入成员墙里面……
> 这次参加活动之前我有看过一遍成员墙所以对一些人会提前有印象，
> 但是发现不是所有人都会把自己的信息写出来，那么就要现场花时间去聊，
> 聊完可能会发现其实别人做的和我好像并不是很有关联。」
>
> James 的印象是「报名表已经会自动进入成员墙」。**这个印象是错的**，下面是实测依据。

### 6.1 实测：报名到上墙有两道闸，转化约 25%

**代码（`src/lib/db.ts`）：**

```
CREATE TABLE members (
  signup_id  bigint NOT NULL UNIQUE REFERENCES signups(id) ...,
  -- NULL while the card is a draft prefilled from the signup.
  -- The wall only ever shows rows where this is set.
  published_at  timestamptz,
  ...
)
```

```
listWallMembers():
  SELECT ... FROM members m JOIN signups g ON g.id = m.signup_id
   WHERE m.published_at IS NOT NULL AND NOT m.hidden
```

**所以有两道闸，不是一道：**

| 闸 | 做什么 | 不做会怎样 |
|---|---|---|
| ① **认领** `/claim` | 填姓名 + 微信号自助匹配，建出 `members` 行 | 库里根本没有这个人的卡 |
| ② **发布** | 在编辑页把卡片设为公开，`published_at` 才被写上（`db.ts:742`） | 卡片是草稿，**墙上看不到** |

**生产实测（2026-08-13）：**

| | 数量 | |
|---|---|---|
| 报名库总人数 | **56** | `snapshots/snapshot-20260813-0949.csv` |
| `vibethursday.com/members` 上已发布的卡 | **14** | 抓页面数 `/members/<slug>` 链接得到 |
| **转化** | **约 25%** | 口径最保守（分母用总库）。只算 08-13 那场的 35 人，也只有四成 |

**四分之三的人不在墙上——反馈说的痛点是实的，不是感觉。**

### 6.2 但「报名就自动上墙」不能直接照做：`building` 这一栏没说过会公开

看报名表现在的文案（`content.ts`）：

| 字段 | 文案怎么说 | 能不能自动公开 |
|---|---|---|
| 邮箱 / 微信号 | 「这两栏**只有我（活动组织者）看得到**。不公开、不给第三方……」 | ❌ 明确承诺不公开 |
| `topic`（这周想聊什么） | 「**它会显示在你成员卡片的「本周想聊」**」 | ✅ 已明示 |
| **`building`（你在做什么）** | 「在做的产品、在折腾的东西……一两句就够。」 | ⚠️ **既没说公开，也没说保密** |

**`building` 正是反馈想要公开的那一栏，而它的文案是空白的。**
直接自动上墙 = 把一段用户以为是写给组织者看的话，未经明示同意变成公开内容。
这是这个站上最不该省的一步——`/support` 那一轮已经因为「删了账本却留着透明措辞」
付过一次代价了。

### 6.3 建议：不是取消同意，是把两道闸压成一个明示的勾选

**改法（一处改动，闸门从 2 变 0，且同意是明示的）：**

在报名表 `building` 那一栏下面加一个勾选框，默认**不勾**：

> ☐ 把「我在做什么」放到成员墙上（`vibethursday.com/members`），
> 方便别人来之前就知道我是谁。随时可以改或者撤下来。

勾了 → `POST /api/signup` 顺手建 `members` 行并直接写 `published_at`，
**不用再走 `/claim`、不用再点发布**。没勾 → 维持现状。

**为什么这样最省：**

- 认领流程 `/claim` 一个字都不用动（老用户照旧）
- 隐私边界反而更清楚了：**从「没说」变成「你自己勾的」**
- 25% 那个漏斗直接被绕开，而不是靠催

⚠️ **仍然要守的**：邮箱和微信号绝不进卡片（现有承诺不能动）。

### 6.4 ★ 顺带一个不该被埋掉的信号

> 「这次参加活动之前我有看过一遍成员墙，所以对一些人会提前有印象。」

**这是成员墙第一次被证明在按设计的方式被使用**——它本来就是为「来之前先知道有谁」造的。
问题不是这个功能没人用，**是墙上只有四分之一的人**，所以看了也只覆盖到四分之一。

**所以 6.3 那个改动的收益不只是「多几张卡」**，是让一个已经被验证有用的功能，
从覆盖 25% 变成覆盖大多数。**优先级应该排在问卷前面。**
