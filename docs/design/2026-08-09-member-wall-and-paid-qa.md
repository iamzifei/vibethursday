# 成员墙（Member Wall）与付费问答：做不做，怎么做

日期：2026-08-09
参考对象：`https://vibecafe.ai/products`（**实测**，2026-08-09 抓取）、`https://new.web.cafe/ask`（**实测**，同日抓取）

---

## 结论

1. **成员墙：做。** 但不要做成「产品墙」，做成**成员名片墙**——一人一张卡，产品只是卡上挂的其中一类资源。
   理由：你的成员天然异质（有产品 / 有业务 / 有自媒体 / 有社群 / 只想旁听 / 只想连 LinkedIn），
   以产品为主体的模型会把 80% 的人挡在墙外，而**空墙比没墙更伤**。
2. **付费问答：现在不做。** 不是设计问题，是供需不成立 + 工程量与收益严重不匹配。
   下面给一个零成本的前置实验，跑三个月拿到真实信号再谈。

---

## 一、为什么成员墙值得做

现在的状态：这些信息全部发在微信群里，**沉在聊天记录里，一周后就找不到了**。

这面墙解决三件具体的事：

| 场景 | 现在 | 有墙之后 |
| --- | --- | --- |
| 「上周那个做 AI 客服的人叫什么？」 | 翻聊天记录，翻不到 | 搜一下就有 |
| 「下周去，能遇到谁？」 | 不知道 | 看这周签到名单 |
| 新人问「这个活动都是些什么人」 | 靠口头描述 | 一个链接 |

这是这个社群**唯一会随时间累积的资产**。每周的活动本身不累积，报名表也不累积（它只是名单），
只有成员墙是越办越厚的东西。同时它天然是最好的招募页——比任何文案都有说服力。

## 二、成员墙的设计

### 2.1 核心模型：身份层 + 资源层

一个人 = 一张卡片。卡片上挂 **0 到 N 个资源**。资源有类型，没有资源的卡片也完全成立。

```
member（身份，一人一条）
  ├── asset: product   「影笺」  阶段=本地跑通   无链接
  ├── asset: media     「小红书 @xxx」  平台=小红书  链接=…
  └── asset: community 「Sydney AI 出海群」 200 人  加入方式=…
```

**这是整个设计的关键。** vibecafe 的模型是「作品 → 挂一个作者」，
你的模型必须反过来：「人 → 挂零个或多个资源」。因为你的成员里，
「人」永远存在，「作品」只是可选项。

### 2.2 资源类型（kind）

| kind | 中文 | 必填 | 可选 |
| --- | --- | --- | --- |
| `product` | 产品 / 项目 | 名称、一句话 | 链接、截图、**阶段**、技术栈 |
| `business` | 公司 / 业务 / 服务 | 名称、在做什么 | 官网、服务对象、想找什么合作 |
| `media` | 自媒体账号 | 平台、账号名 | 链接、粉丝量（选填）、内容方向 |
| `community` | 社群 | 名称、面向谁 | 规模、加入方式 |
| `profile` | 个人链接 | 平台（LinkedIn / X / GitHub） | — |

### 2.3 「没上线 / 只在本地 / 根本没产品」怎么办

这是你最担心的点，答案是：**不要用「上线与否」做门槛，把它降级成一个标签。**

产品卡有一个 `stage` 字段，五档：

```
💡 想法阶段    🔧 本地跑通    🧪 内测中    🚀 已上线    💰 已有收入
```

三个直接后果：

- **没链接不是缺陷，是一种状态。** 没有 URL 的卡片照样渲染完整，只是不显示「访问」按钮。
- 在一个 builders 聚会里，「本地跑通」比「已上线」**更有话题性**——它意味着这人正卡在某个地方，
  而现场可能就有人能帮他。这恰恰是线下活动的价值所在。
- 有了 stage，墙本身变成了进度可视化。同一个人的产品从 🔧 变成 🚀，是社群最好的内容素材。

**并且必须允许 0 资源的会员卡。** 旁听者的卡片是这样的：

```
张三  @zhangsan
在传统行业做供应链，最近在自学 AI，想看看别人都在做什么
🏷 旁听  ·  出席 2 次
🔎 想找：能聊聊 AI 在制造业落地的人
```

这张卡完全成立，而且对社群有用。如果只有有产品的人能上墙，这个人不会填，
另外二十个像他这样的人也不会填，墙就是空的。

### 2.4 两个字段决定这面墙有没有用

除了自我介绍，每张卡强制引导填这两个（都可留空，但 UI 上要显眼）：

- **🔎 想找什么**（looking_for）——「找会 iOS 的合伙人」「想找第一批种子用户」「想找人聊出海支付」
- **🤝 能帮什么**（can_help）——「做过三年 Google Ads」「悉尼公司注册踩过坑」

一面只有「我是谁」的墙是通讯录，加上这两栏才是**撮合器**。
这也是后面判断「付费问答该不该做」的数据来源（见第三节）。

### 2.5 排序与筛选：不要抄 vibecafe

vibecafe 有排行榜、有分类/平台/状态三连筛。**不要抄。** 他们需要那些是因为量大，你不是。

- **主排序 = 最近出席**，不是点赞。这是线下社群，墙的用途是「谁会来 / 谁来过」。
  点赞排序奖励的是会营销的人，会直接伤害你现在的氛围。
- **筛选只做两个**：身份类型（Builder / 有业务 / 创作者 / 社群主理人 / 旁听）+ 标签。
- **按周分组这个可以抄**（vibecafe 的 `本周：08/09 - 08/15`），而且你比他们更适合——
  你有真实的场次。首屏就是「本周四会来的人」，往下是历史。

### 2.6 认领机制：不要做注册

**不做通用注册系统。** 用已有的 `signups` 表认领：

1. 报名过的人，用报名时的 email / 微信号认领 → 发一次性链接（magic link，15 分钟有效）
2. 认领后可编辑自己的卡片，链接可反复用（存在 cookie 里）
3. 没报名过的人上不了墙

三个好处：墙上只有真来过的人；不需要密码/账号体系；天然反 spam。

### 2.7 冷启动：这是最容易失败的地方

**风险不在设计，在于没人填。** 一面填了三张卡的墙，比没有墙更难看。

现有的 `signups` 表里已经有 `building`（在做什么）和 `topic`（这周想聊什么）——
**直接用这些数据预生成草稿卡**，然后发认领链接：
「这是我们根据你报名时写的内容帮你生成的卡片，改两个字就能发布。」

让人**修改**比让人**从零写**的完成率高一个量级。这一步做不做，决定这个功能的死活。

配套动作：现场把墙投影出来，60 秒自我介绍时打开对应的卡片。

### 2.8 隐私

- 每张卡三档可见性：公开 / 仅成员可见 / 隐藏
- **微信号永远不在公开页显示**（现在 `signups.wechat` 是私密数据，别泄漏进墙里）
- email 同理，只显示成员自己主动填的公开联系方式

## 三、付费问答：现在不做

### 3.1 web.cafe 那套的实际机制（**实测**）

- 答主设定单次提问价 **100–1000 元**，会员半价
- **平台不抽成**，提问费全额给答主
- 问答默认私密，双方同意后可公开；第三方付 **1 元**围观完整问答，1 元由提问者和回答者各分 0.5 元
- 有打赏（6.66–1000 元）、点赞、钱包提现（单笔上限 200 元）

### 3.2 为什么这套在你这里不成立

**(1) 供需前提不同。** 付费问答成立需要三个条件同时满足：
提问方基数大 × 答主稀缺 × **双方互不认识**。
你现在是每周一次、几十人、面对面、还都在同一个微信群里。
**在群里 @ 一下就能问到的东西，没有人会付 100 块。** 这不是定价问题，是渠道问题。

**(2) 它会破坏你现在最值钱的东西。** 线下社群的核心资产是「互相帮忙」的默认氛围。
过早引入定价，会把互惠关系转成交易关系——一旦有人开始标价，
免费帮忙的人会觉得自己亏了，而这个转变是不可逆的。

**(3) 工程量与收益完全不匹配。** 这个站现在是「一个表单 + 一张表 + 无账号体系」。
付费问答需要：账号体系、钱包、余额、微信支付/Stripe 接入、分账、退款、
内容审核、纠纷仲裁、提现。这是**全站最大的一笔工程投入**，
换来的收入天花板 = 几十人 × 极低付费率 × 抽成（连 web.cafe 都不抽成）≈ 0。

按优先级排序（影响营收 > 阻塞发布 > 体验打磨），它三条都不占。

### 3.3 零成本前置实验

不用写任何代码就能验证这个功能该不该做——**用 2.4 节的「🔎 想找什么」当免费版的提问**。

观察三个月，看这三个信号：

| 信号 | 说明什么 |
| --- | --- |
| 免费求助**发得少 / 没人回** | 需求根本不存在，付费版必死。结论：永远不做 |
| 免费求助活跃，互相帮忙很顺畅 | 需求存在但**已被满足**，加收费只会添堵。结论：不做，保持现状 |
| 某个人被反复私聊问同类问题，**且他开始嫌烦 / 开始婉拒** | 这才是定价信号——定价的作用是**筛掉低质量提问**，不是赚钱 |

只有第三种情况出现，才值得回头看这个功能。而且到那一步，
最小可用版本也不是 web.cafe 那一套，而是：**那一个人的一个页面 + 一个 Stripe payment link**。
不需要钱包，不需要分账，不需要围观解锁。

## 四、实施建议（如果决定做成员墙）

### 4.1 数据模型草案

```sql
-- 身份层
CREATE TABLE members (
  id            bigserial PRIMARY KEY,
  signup_id     bigint REFERENCES signups(id),  -- 认领来源，保证真来过
  slug          text UNIQUE NOT NULL,           -- /members/zhangsan
  display_name  text NOT NULL,
  headline      text,                           -- 一句话介绍
  bio           text,
  avatar_url    text,
  roles         text[] NOT NULL DEFAULT '{}',   -- builder/business/creator/organiser/listener
  looking_for   text,
  can_help      text,
  tags          text[] NOT NULL DEFAULT '{}',
  visibility    text NOT NULL DEFAULT 'public', -- public/members/hidden
  published_at  timestamptz,                    -- NULL = 草稿（预生成但未认领）
  created_at    timestamptz NOT NULL DEFAULT now(),
  updated_at    timestamptz NOT NULL DEFAULT now()
);

-- 资源层
CREATE TABLE member_assets (
  id          bigserial PRIMARY KEY,
  member_id   bigint NOT NULL REFERENCES members(id) ON DELETE CASCADE,
  kind        text NOT NULL,   -- product/business/media/community/profile
  title       text NOT NULL,
  tagline     text,
  url         text,
  image_url   text,
  stage       text,            -- 仅 product：idea/local/beta/live/revenue
  platform    text,            -- 仅 media/profile：xhs/wechat/x/linkedin/youtube…
  meta        jsonb NOT NULL DEFAULT '{}',  -- 粉丝量、社群规模等低频字段
  sort_order  int NOT NULL DEFAULT 0,
  created_at  timestamptz NOT NULL DEFAULT now()
);
```

沿用 `src/lib/db.ts` 里 `ensureSchema` 的写法（`CREATE TABLE IF NOT EXISTS` + `ALTER … IF NOT EXISTS`），
保持「无迁移步骤」这个现有约定。

出席次数直接用 `signups.sessions date[]`，不需要新字段。

### 4.2 页面

| 路由 | 内容 |
| --- | --- |
| `/members` | 墙。首屏「本周四会来的人」，下面按最近出席排序，两个筛选器 |
| `/members/[slug]` | 单人详情页，可分享（这是成员愿意填的最大动力） |
| `/claim` | 输入 email/微信号 → 发认领链接 |
| `/me` | 编辑自己的卡片和资源 |

文案照现有约定全部进 `src/lib/content.ts`，中英双语并排。

### 4.3 范围控制

**第一版只做**：认领 + 编辑 + 墙 + 详情页。
**第一版不做**：图片上传（先只支持贴外链，或干脆没有图）、点赞、排行榜、评论、搜索。

估算（**推断**，基于现有 codebase 的规模和风格）：2 张表 + 4 个路由 + 3 个组件，约 600–800 行，
半天到一天。**如果我错了，最可能错在图片处理上**——一旦要做上传就得引入对象存储，
那是另外半天，所以第一版刻意不做。
